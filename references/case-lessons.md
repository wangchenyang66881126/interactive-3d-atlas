# 案例与修正规则

这些是 Model 3 → SU7 Ultra 风格 → Boeing 787 → 萧山机场 T3 出发层这组制作在 2026-09-08 形成的经验。不是新的场所事实、工程认证或固定验收数值。后续优先使用当前用户要求和重新核对的资料。

## 特斯拉 Model 3

用户将目标从简化展示提高为接近实车的可旋转、拆解、点选网页，后来接受相似效果。有效做法是保留社区模型的真实曲面、纹理坐标和外观总成，再补有说明的内部结构；不能继续用低细节方块外形仅换一个标题。

前盖穿模的具体来源是后加热管理硬件。修正进入总成原点后，逐帧拆解和复位不会把它重新移回错误位置。泛化规则是持久修正装配基准，不是每个模型都向下移动固定距离。

哑光黑只修改车身涂装材质，保留玻璃、轮胎及其他表面差异。“黑色”与“哑光”是两个维度，不能只改色号。

## 小米 SU7 Ultra 风格

复用图鉴界面和拆解机制，但替换为 SU7 外观资产。基础 SU7 加 Ultra 风格细节需要明确修改和示意边界，不冒充原厂 Ultra 工程数据。案例使用的几何有 CC BY 4.0 归属和修改说明；新资产仍需独立核对许可。

用户多次调整天蓝／青蓝、深邃程度、顶部灯光、背景和投影，说明应将车漆、反射、补光、背景、地面独立调节。纯黑背景曾是阶段要求，之后“看清投影”成为新的要求；不要将任一阶段固化为永远的默认。

徽标使用正确 MI 图形并投射到前盖曲面，绑定前盖总成。其通过顶点间隙与归属检查，不依赖用某个角度掩盖穿模。案例的毫米间隙仅适用于当时模型尺度。

## 白色 Boeing 787

用户明确纠正“要爆炸图展示，不是 Blender 源文件”，所以三维交互网页是交付。原始机体几何、内部示意与后续驾驶舱增强分别管理；不能把网页制作过程中的源文件当成最终目标。

坐标转换影响拆解向量；相机必须适应长机身和大翼展。驾驶舱增加屏幕、操纵机构、推力杆、顶板、座椅约束等独立细节，并添加随展开变化的局部目标。静态仪表内容按示意处理，避免声称是实时飞行系统。

## 萧山机场 T3 出发层

初版错误来自沿用历史 T1／T3 分区裁切底图，导致门和岛台遗漏。机场乘机指南当时直接链接的地图包括 5、7、9、11、13 号出发门，C 至 H 六个值机区，其中 E 区画为两个岛台。修复需要重新确定整段大厅范围，不只是补几个数字。

上述门号和岛台是案例核对结果，不作为其他机场或未来 T3 的预设。发布或抓取日期较新的商业 PDF 仍可能保留旧布局，因此要检查图的实际内容和当前官网引用关系。

母婴室此前已有若干点位，但缩小时全部隐藏文字造成“不见了”的体验。后续同时完善数据与可见性：六处出发区域母婴室包含 B95 旁需换层到达的一处；用换层入口方向表示，未把目标房间放到 3F。

贵宾六号厅、贵宾接待中心和厦航休息室分别查机场与运营方资料。厦航页面当时列在 B40 对面，而非沿用早期 B25 的描述。增加分类图标、快捷筛选、文字避让和安检前后说明，比无来源地增加房间数量更有用。

## 复用时的边界

- 可复用：状态模型、语义拆分方法、证据字段、材质分工、反馈诊断、交互行为与交付检查。
- 重新核对：对象版本、资产许可、内部结构、实际标志、场所分区、设施位置、开放时间、电话号码。
- 不携带：旧网站项目 ID、私人域名、访问令牌、用户数据、缓存、部署归档或未授权模型副本。

典型调用：

- “用同样的方法做一辆白色跑车，可旋转、拆解、点选部件。” → 确认可推断的车型版本，先做形态正确的独立资产与总成。
- “车盖又穿模了，修一下。” → 定位装配基准或变换问题，验证复位和拆解状态；保留其他效果。
- “这架飞机的驾驶舱再丰富一点。” → 延续已有飞机网页，仅完善机型相符的内部总成和局部观看。
- “机场母婴室也标出来。” → 核对当前楼层与官方地标，同时检查已有点位是否被隐藏。
- “只给我 Blender 可编辑文件。” → 切换模型导出分支，不把网页发布当作交付。
